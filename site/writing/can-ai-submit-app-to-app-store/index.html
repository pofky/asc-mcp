What an agent can do

With an App Store Connect API key, an agent can run the release in order. The chain asc-mcp follows is: setup_app_store_signing, build_and_archive, upload_binary, wait_for_build, attach_build, update_version_metadata, upload_screenshots, then set_app_metadata, set_app_price, set_app_availability, set_age_rating and set_review_contact. release_preflight audits the version before submit_for_review, and after approval release_version publishes it, or manage_phased_release starts a 7-day rollout.

The /asc-ship-release slash command drives that sequence and stops to confirm before every outward-facing step.

What a person still does

  • Create the app record. POST /v1/apps is refused for API keys, whatever role the key holds. In the website: Apps, the plus button, then bundle ID, SKU and primary language. Everything after that is writable over the API.
  • Submit the first in-app purchases. Apple wants an app's first products reviewed together with a version, and only the website can bundle them. Open the version, use Add for Review, tick the products and submit them together. Later products submit over the API.
  • Answer the App Privacy questions. The data usage resource is not public in the API. set_privacy_nutrition returns the checklist and the link to the page, and Apple will not accept a submission until it is answered.
  • Declare EU trader status. Also website-only. set_eu_trader_status returns what to fill in and where. Without it the app cannot be offered in the EU.
  • Wait for Apple. Reviewers approve or reject. The agent can read the review status and submit again, and cannot change the decision.

The first four are among the limits on what the App Store Connect API cannot do, with the error each one returns. asc-mcp flags each one before you start, with the steps, instead of pretending the call exists.

Try it

Add the server, then paste your Issuer ID into the chat and it connects. Setup steps.

claude mcp add asc-mcp -- npx -y @pofky/asc-mcp

The binary builds on your Mac

Submission needs a build, and a build needs Xcode. build_and_archive runs xcodebuild locally and upload_binary sends the .ipa with altool and your API key. Nothing is compiled in the cloud.

Nothing is submitted by accident

Three tools refuse to run without an explicit confirm: true: submit_for_review, release_version and upload_binary. The guide the agent reads says to confirm with the human first.

submit_for_review  { "app_id": "...", "confirm": true }

When first in-app purchases are present, submit_for_review detects it and aborts before it submits anything, so the version is not left half submitted. The agent is told to do that step in the website.

How it connects

Add the server, then give the agent your Issuer ID. It calls asc_connect, which finds the downloaded .p8, tests it against Apple and unlocks every tool in the same chat. Steps are under setup on the home page. asc_guide returns the playbook for a first release and marks each manual step in order.

Questions

Can an AI agent submit an app to the App Store?

Partly. An agent connected to the App Store Connect API can attach a build, set metadata and pricing, upload screenshots and call submit_for_review with confirm: true. A person still does four things on the website: creates the app record, answers the App Privacy questions, declares EU trader status, and submits an app's first in-app purchases with the version. Apple's reviewers decide the outcome.

Can an AI agent create the app record in App Store Connect?

No. POST /v1/apps is refused for API keys, whatever role the key holds. The app record is created once in the App Store Connect website by a person, after which everything about it is writable over the API.

Can an agent submit an app's first in-app purchase?

Not through the API. Apple requires an app's first in-app purchases to be submitted with an app version, and only the website can bundle the two. submit_for_review detects this and aborts instead of orphaning the version. Later products submit over the API.

Can an AI agent build the app binary?

Yes, on your Mac. The build_and_archive tool runs xcodebuild through Xcode, and upload_binary sends the .ipa to App Store Connect with confirm: true. The build does not run in the cloud, so Xcode must be installed locally.

Who decides whether the app is approved?

Apple's reviewers do. An agent can submit the version and read its review status, but approval is Apple's decision, and nothing in the API or in asc-mcp can change it.
